## VNE_TECH_SURVEY_2026-07 (`.docx` = оригинал, `.txt` = извлечённый текст для grep/цитат)

Обзор индустрии AI-персонажей 2025–2026 с честной маркировкой уверенности (High/Low
Confidence, девять неразрешённых Conflict Zone). **Независимо валидирует** архитектуру VNE
(ФМДР, allowlist-Gateway с provenance, трёхуровневое одобрение, «память раньше fine-tune»,
local-first, router-над-Gateway, эволюция ролей через proposal+approval).

Прикладные разделы по трекам:

| Трек | Раздел отчёта | Что берём |
|---|---|---|
| **PAC (N9)** | §2.4, §3.4.2, §9 (I8) | eval как часть v0 (фиксированные пробы + калибровка судьи + min-per-turn); PAC-память = Markdown+frontmatter, «писать только недериваемое»; reassemble-per-turn |
| **Sandbox (D-CES)** | §3.4.1, §4.4 | event-sourced SQLite+FTS5+WAL, `branch_id`+snapshots, embeddings отложены (>5–10k); гранулярность «на сюжетное событие»; 5 гейтов промоушна; дифференциальный протокол узнаваемости (D-CES-6) |
| **Roles/Routing (D-RKR)** | §5.4 | тонкий детерминированный router над Gateway (фильтр→семантика→LLM), agents-as-tools; registry = git-коммиты+теги, proposal = PR + eval-гейт ≥95%, rollback = перемещение тега; предупреждение ClawHavoc |
| **N8 (fine-tune)** | §6.5 | база **Qwen2.5-7B / Qwen3-8B** (мультиязычность); `raw`/`approved` = DPO-пара; порог авторизации ≥150–300 approved + holdout + канон-пробы |
| **Ren'Py + LLM** | §8.1.2 | чистые данные vs кэш вставок; LLM-реплика пишется в историю как факт, не регенерируется при rollback; миграция save-файлов по версии профиля |

Сквозные инсайты: I3 память раньше fine-tune · I5 контекст-инженерия = высший ROI ·
I8 eval = главный системный риск (LLM-судьи принимают до 63% неверных ответов).

**Дисциплина:** ни одну цифру не принимать за истину — отчёт сам маркирует вендорские
claims и Conflict Zone как неразрешённые. Источник = вход для решений, решения ратифицирует владелец.
